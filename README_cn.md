## 二、设备组成

### 2.1 RDK X5主控平台

本车采用地瓜机器人RDK X5作为唯一任务主控。开发板搭载八核Arm Cortex-A55处理器和10 TOPS INT8 BPU，运行地瓜官方适配系统与ROS 2环境。黄色通道感知和场景目标检测在BPU侧执行，路线调度、二维码解码、里程统计、语音管理和屏幕显示在CPU侧协同运行。

RDK X5由官方渠道取得，使用官方系统镜像、模型转换工具、TROS功能包和硬件接口资料进行开发。其USB、HDMI、网络、TF卡及底盘通信接口满足车载感知、计算和交互需要。

### 2.2 车载设备清单

| 模块 | 设备 | 任务作用 |
|---|---|---|
| 视觉输入 | RDK兼容摄像头 | 获取赛道、二维码、障碍物、通道口、人形立牌和P区图像 |
| 运动执行 | ROS 2兼容车模底盘 | 接收统一速度指令，完成巡线、绕行、转向及停车 |
| 人机交互 | HDMI车载显示屏、扬声器 | 显示二维码和图生文结果，同时播报方向及人物描述 |
| 供电存储 | 稳压电源、动力电池、高速TF卡 | 提供持续供电并保存系统、模型、程序和日志 |
| 结构附件 | 散热组件、USB扩展、固定件与线束 | 保障散热、接口扩展和整车连接可靠性 |

### 2.3 连接关系

| 摄像头输入 | → | RDK图像编解码 | → | BPU双路感知 | → | 路线指挥器 |
|---|---|---|---|---|---|---|
| 里程计 | → | 圈长累计与返航定位 | → | 速度仲裁 | → | 底盘执行 |
| 人形截图 | → | 图生文服务 | → | 屏幕显示＋语音播报 | → | 任务完成反馈 |

相机经USB接口连接RDK，显示屏经HDMI连接，底盘驱动通过车载通信接口接收速度命令。动力线路与计算线路分路稳压，全部线束固定在车体结构内。

## 三、技术方案

### 3.1 双依据闭环任务流程

二队以“视觉入口复检”和“里程计累计”共同判断C区完整巡航，防止仅凭时间或单帧地标误判一周。

| 任务发布点 | → | 识别二维码并播报方向 | → | 指定通道入C区 |
|---|---|---|---|---|
| 黄色通道循迹＋里程累计 | → | 人形图生文双输出 | → | 入口复检后离场 |
| 返回起始坐标/P标识 | → | 精细定位停车 | → | 全车保持静止 |

二维码识别模块输出原始数字和方向编码。不同方向编码产生相反的分岔角速度，路线指挥器据此选择顺时针或逆时针路径。二维码原文、运行方向和图生文结果由车载面板显示，语音模块同步播报方向及人物描述。

进入C区后，中心线感知模块持续输出黄色通道中心，轨迹跟随器形成候选速度；场景感知模块检测障碍物、通道口、人形立牌和P点，障碍物控制器形成绕行速度。路线指挥器是最终速度命令的唯一发布者，根据风险状态选择巡线或绕行指令。

巡航开始时记录累计里程基准。车辆达到有效环行里程、再次检测到通道入口且已取得人形描述后，才转入离场状态。返航阶段同时使用起始里程坐标和P点视觉标识触发精细停车。

### 3.2 软件构成

| 功能单元 | 实现内容 |
|---|---|
| 图像管线 | 摄像头采集、JPEG/NV12转换及ROS 2图像发布 |
| 路径感知 | 板端黄色通道中心线模型 |
| 环境感知 | 板端障碍物、通道口、人形和停车标识模型 |
| 任务获取 | 二维码原文解析、数字校验及方向编码 |
| 路线调度 | 八阶段路线状态、里程累计、入口复检和180秒截止 |
| 运动执行 | 巡线候选、绕障候选、指令超时检查及统一仲裁 |
| 场景理解 | 人形截图、多模态图生文和结果回传 |
| 信息发布 | 蓝色车载信息面板与TTS语音播报 |

工程只保留中心线、场景防护和人形场景三类实际使用的模型能力，不设置N、S、GO或BACK模型目录。方向切换由二维码数据驱动，模型无需重复切换。

### 3.3 规则执行

子任务一阶段，车辆自主抵达任务发布点，读取二维码并显示原始数字、播报顺逆时针方向。子任务二阶段，车辆经指定通道进入C区，沿黄色环形通道按指定方向运行；检测人形后自动抓图，生成文字并通过屏幕和语音同步反馈；满足里程与入口双条件后从B区通道退出。子任务三阶段，车辆依据起始坐标和P标识返回停车区，完成自主静止。

全局计时从主控启动时开始，180秒到时立即进入安全停止状态。候选控制消息超时、任务完成或程序退出时，同样持续发布零速度。

## 四、开发依据

1. RDK X5硬件规格、系统镜像和接口使用方法来自地瓜机器人官方文档。
2. 相机、图像编解码、BPU模型部署和ROS 2通信采用地瓜官方TROS工具链及示例功能包。
3. 视觉模型通过地瓜官方模型转换与量化流程部署至RDK X5。
4. 底盘基础驱动采用官方兼容ROS 2接口；路线指挥、里程判圈、速度仲裁、图生文交互和信息面板为赛事应用层程序。
5. 图生文访问凭据通过车载系统环境变量加载，不写入提交源码。

## 五、赛场保障

### 5.1 启动保障

采用一体化启动文件拉起底盘、相机、图像转换、感知、二维码、任务控制、图生文、屏显和语音节点。启动完成后由各节点发布状态，关键数据缺失时最终控制器保持零速度。

### 5.2 运行保障

- 黄色通道短时丢失时限制速度，控制消息超过有效期后停止使用旧指令。
- 障碍物出现时绕行指令获得优先权，避免碰撞及推动障碍物。
- 里程增量设置跳变过滤，抑制定位丢帧造成的虚假圈长。
- 二维码采用合法值校验，方向只在任务获取阶段锁定一次。
- 人形描述为空或请求失败时不判定图生文完成，车载终端显示处理状态。
- P点停车采用视觉标识和起始坐标双通道触发，提高返航停车可靠性。
- 180秒截止、正常完成及程序退出均进入零速度锁存。

### 5.3 备份保障

系统镜像、模型和程序保存在主用与备用TF卡；车队配备备用相机、电源线和固定线束。赛前完成顺时针、逆时针、障碍物、人形图生文、入口复检、返航停车和180秒截止的完整联调。
